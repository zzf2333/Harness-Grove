## W1 偏好：把“先复述问题再回答”改成“先给结论，再复述问题”

| 项 | 内容 |
|---|---|
| 改动性质 | 用户明确的偏好 |
| 目标文件 | `config/AGENTS.md` 第 2 行 |
| 证据指针 | 会话 L6（用户自述固定偏好）；`config/AGENTS.md` L2（现有要求与之冲突） |

- 为什么改：用户明确要求“以后每次回答都先给结论，再解释理由”（会话 L6）；配置第 2 行要求先复述问题再回答，与新偏好冲突
- 改后期待什么：先给结论，再复述问题；不丢“用户说先别做时，不要越界执行”这条约束
- 凭什么判断：读一遍：措辞是否准确表达偏好、是否与其余行冲突；偏好不需要证明更优

```diff

+++ b/config/AGENTS.md
@@ -1,3 +1,3 @@
 先给结论。
-先复述问题再回答。
+先给结论，再复述问题。
 先给结论。
```

## W3 假设：把“不要顺手做相邻改动”写进越界约束（收益待验证）

| 项 | 内容 |
|---|---|
| 改动性质 | 想减少失误的假设 |
| 目标文件 | `config/AGENTS.md` 第 4 行 |
| 证据指针 | 会话 L9、L12（两条用户叫停）；L10 助手调用 `edit` 改 `README.md`、L11 工具结果“已写入 README.md”（唯一可见的相邻文件写入，在 L9 明确叫停之后）；`config/AGENTS.md` L4（现有约束只写“先别做时不越界”） |

- 为什么改：原文有两条叫停（L9、L12），但相邻文件的越界写入只有一次：L10 助手调用 `edit` 改 `README.md`、L11 返回“已写入 README.md”，且发生在 L9 明确叫停之后。L7、L8 改的是 `config/AGENTS.md`（L2 用户本来就要求整理它），不能算相邻越界。材料只支持“一次可见越界 + 两条叫停”，不能计成两次独立越界；配置第 4 行只写“先别做时不要越界执行”，没写不能顺手做相邻改动
- 改后期待什么：越界后需要用户叫停的情况减少；不丢原有“先别做时不越界”约束
- 凭什么判断：收益待验证：本轮不做行为实验，单条合成会话也说不出真实环境里的越界频率；用户批准真实应用后，在观察窗内统计越界后需要叫停的次数

```diff
--- a/config/AGENTS.md
+++ b/config/AGENTS.md
@@ -3,3 +3,3 @@
 先给结论。
-用户说先别做时，不要越界执行。
+用户说先别做时，不要越界执行，也不要顺手做相邻改动。
 复盘时先读账本。
```
