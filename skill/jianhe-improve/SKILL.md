# 用户核心演进、方案探索与跨工具投影

## 目的与设计理由

在 Jianhe 中，**人是唯一主体**，所有 Agent 与工具只是围绕用户内在核心存在的可替换投影与执行器。本入口回答：怎样把一个新目标、外部想法或复盘发现的机会，变成贴合这位用户工作核心、负担可控、随时可退出的实际工作方式与跨工具投影？

别人奏效的复杂编排未必适合当前用户，堆砌规则与工具更不等于改善。设计方案必须先对齐用户的核心目标与标准，讲清改后**人怎样开始任务、在哪里做判断、最终省掉哪一步摩擦**，而不是只甩出一堆工具名或配置片段。依靠宿主已有的读取、搜索、文档查询、编辑与执行能力独立运作，不依赖项目 CLI 或其他 Skill。

## 1. 建立日志、核心定锚与检查 WIP 门禁

读取请求后，按 [用户核心、跨工具投影与操作契约](./references/contract.md) 第 2 节确定四级日志位置并核实可取得的本次宿主轨迹线索，尽早建立或续写 `log.md`；接手同次任务时共用原日志，不重复访谈。

- **核心定锚**：读取 `CORE.md`、根 `README.md` 看板与相关既有事项（需要读取会话或授权项目产出补充背景时遵循 [用户信号、项目产出与跨 Agent 记录读取](./references/signal-reading.md)），明确本次需求**服务哪条已确认核心 `C<n>`，或消除哪条工具迁就 `A<n>`**。若用户尚无 `CORE.md` 或该诉求尚未入核，先帮用户提炼一句可观察的工作要求确认入核，或将方案明确标为“核心依据待确认”；若由日常会话中途转交候选落盘，直接按 [contract.md](./references/contract.md) 第 1.1、2、3 节执行完整日志与写入门禁。
- **有界看板 WIP 门禁**：核查根 `README.md` 的 `在验证` 活跃数量（默认上限 **5 项**）。当 `在验证` 已满额时，**停止推进任何新增复杂度的落地方案**（新规则、新角色、新脚本、新第三方工具），先向用户说明容量阻塞并引导结算旧事项腾位（可衔接 `jianhe-maintain` 或在本入口按契约结算）；纯删减精简、故障修复、三方恢复、漂移对齐及 `CORE.md` 候选确认/拒绝不受阻塞。
- **外部想法去魅**：输入来自外部文章、分享的 Skill 或热门工具时，先拆解它试图解决什么真实问题、依赖什么前提，区分作者宣称与本地事实；现场与已有维护说明不一致时先查清差异，绝不照旧说明覆盖用户手改。

## 2. 研究并核对能力前提

围绕“支撑该核心目标或消除该迁就需要什么能力”开展有界研究，既查现有工具未用好的原生能力，也查工具重组合与第三方方案，不预设必须装新软件：

- 查阅对应版本的官方文档、帮助与变更记录，结合本地版本、配置与只读探针核实当前环境可用性，严格区分“宣称支持、当前版本支持、本地已启用、用户实际受用”。
- 记录关键依据链接或本地位置、版本号、核对日期、适用条件与未知项；来源不可达或前提未核实时如实告知并给出最小核实办法，暂不进入依赖该前提的写入操作。

## 3. 比较做法并设计以人为中心的工作流与投影

以当前做法为基准，横向比较**保持现状、调整用户自身工作步骤、用好已有功能、跨宿主投影、引入外部工具**五种路径，在 `log.md` 用独立 `### P1`、`### P2`（或续接原日志 `#p<n>`）串起：**服务锚点（`C<n>`/`A<n>`）→ 当前摩擦与证据 → 已查证能力 → 改后工作步骤 → 为什么贴合该用户 → 代价、反例与未知项 → 验证与退出办法**。

- **讲清人机协作闭环**：单工具小改写明改前改后即可；涉及多工具或多 Agent 协作时，必须写明谁理解需求、谁执行、谁独立验证（不按品牌绑定死角色）、上下文与产物怎样交接、**用户在哪个节点拍板验收**，以及不顺手时如何零残留退回。
- **明确投影方式与映射草案**：按 [contract.md](./references/contract.md) 1.2 节选定集中内容源、原位配置说明或外部工具登记，给出 `assets/<名字>/README.md` 的**核心投影映射表**草案（标明 `C<n>` / `A<n>消除` / 工具局部适配）及受影响的所有宿主入口，不假定共享文本天然跨宿主等效，也不复制整份宿主配置充当第二来源。
- **可选接入投影轻约定**：首次建立跨工具共享 `AGENTS.md` 或用户希望在日常会话低摩擦捕获新偏好时，可按 [contract.md](./references/contract.md) 1.4 节原样提供投影轻约定供用户单独批准（填入下次建议复盘日，不改写或缩写片段，说明该约定不读写用户目录）。

## 4. 按具体批准备份、落地与读回验证

用户仅要求评估或设计时交付方案即止。获准试用或实施时，严格履行 [contract.md](./references/contract.md) 第 2、3 节：

- 展示目标路径、待改现状、具体改后内容或命令、受影响宿主范围、费用与恢复办法；多项建议只执行用户明确批准的条目（第三方安装、权限变更、付费、推送或部署均须明确批准）。
- **写前必做**：核对目标现场，保存并**读回确认可用**的改前恢复依据（存入本次 `backups/` 或记清版本引用，不含凭证值），在 `log.md` 写妥方案、批准原话/位置与范围后才动目标文件。
- **写后必核**：逐项读回比对实际差异，区分已写入、已核对、未执行、失败或部分完成；失败即停依赖步骤，不自动整包回滚。仅改变人工用法时直接给出可照做的操作卡与试用场景，不强写配置。

## 5. 登记有界看板与诚实交付

获准实施完成后，同步更新 `CORE.md`（若含本次确认条目）、`assets/<名字>/README.md` 映射表及根 `README.md` 看板，向用户交付：**改后怎样完成一次真实任务 → 本次实际改动与映射溯源 → 恢复办法 → 下次如何检验收益 → `log.md` 路径**。

- **`在验证` 四要素必填**：凡新增复杂度的获准落地项，入根 `README.md` `在验证` 池时必须写全**服务锚点（`C<n>`/`A<n>`）、用户可感知正信号、代价与反向信号、到期条件（默认 30 天或 3 次相关真实任务）**，并更新下次建议复盘日；暂缓或待定项按上限规则记入 `待决定` 或留存日志。
- **分开报告三层状态**：明确区分配置写入成功、宿主已加载生效、真实工作行为改善；未经过后续真实任务观察前，实际收益一律标为**未知**。

## 不可妥协的九条硬底线

1. **人是唯一主体，防黑盒揣测**：`CORE.md` 只记可观察的工作要求，严禁推断人格、情绪或心理动机；观察习惯须有 `≥2` 个独立事件指针才提议候选；未经用户确认不建改 `CORE.md`，候选、已拒绝项与 `A<n>` 迁就严禁投影进宿主配置（[contract.md](./references/contract.md) 1.1 节）。
2. **迁就不当偏好固化**：因工具缺失或接口笨拙被迫重复的手工补救归入 `A<n>` 作为消除靶子，绝不当成用户偏好写进指令永久固化（除非用户明示希望保留人工操作）。
3. **有界在制防账本化**：活跃看板默认 `在验证 ≤5`、`待决定 ≤5`，不在根 `README.md` 建池外影子清单；`在验证` 满额阻塞新增复杂度方案（仅豁免纯删减、故障修复、三方恢复、漂移对齐与 `CORE.md` 确认）；到期无正向用户证据默认提议精简或撤回（[contract.md](./references/contract.md) 1.3 节）。
4. **日常零目录读写开销**：普通项目任务不读写 `.jianhe/`；可选投影轻约定只做收尾询问与输出 `[Jianhe 待落盘]` 会话锚点线索（线索不是记录或日志）或转交 Jianhe Skill，裸片段绝不直接写文件（[contract.md](./references/contract.md) 1.4 节）。
5. **两层记录与四级日志位置**：原生轨迹核对实际调用，Markdown 及时按批记证据、决策、批准与结果，禁拖到结束补写；日志位置按“本次明确指定 → 接续原日志 → 用户已明确设置的保存位置 → 默认 `.jianhe/logs/`”解析，写入失败或拒绝保存时暂停新的正式分析与修改，仅做必要只读状态核对并报告，恢复后先补明状态（[contract.md](./references/contract.md) 第 2 节）。
6. **写入前硬门禁**：任何 `CORE.md`、资产、宿主配置写入或第三方软件安装/卸载前，必先核对现场、在日志记清具体方案与用户本人批准原话/位置及范围、保存并读回确认可用的改前恢复依据；只读分析不顺手建资产或改环境说明（[contract.md](./references/contract.md) 第 2、3 节）。
7. **三方比对恢复与手改优先**：用户手改 `CORE.md` 或宿主配置永远优先，不为符合文档覆盖手改；撤回改动须三方比对“原改前 / 实际改后 / 当前现场”，只生成反向差异并保留后续修改，冲突或依据不足时暂停报告（[contract.md](./references/contract.md) 1.2、3 节）。
8. **诚实区分写入、加载与真实收益**：文件修改成功、宿主已加载、实际工作改善分开报告；`N=0` 无观察机会效果保持未知（禁写 `0%`），缺失不补零，不从 Token 推算实付费用，演练合成材料严格隔离（[contract.md](./references/contract.md) 第 4 节）。
9. **有界读取与隐私脱敏**：只读授权会话、当前/指定项目仓库与受管配置，不扫全盘无关私人目录；外部检索不上传私人会话、配置、源码或凭证值（[signal-reading.md](./references/signal-reading.md)）。
