# 用户信号、项目产出与跨 Agent 记录读取

这是只读信号识别与增量读取指导，不是解析器或固定格式协议。使用宿主已有的文件、搜索或只读会话接口；不启动额外模型会话来“重建历史”，不安装采集工具，不改写原始记录。

## 读取优先级与核对依据

读取材料围绕“理解人的真实目标、工作标准与受限摩擦”展开，按以下优先级分配注意力，避免把分析做成单纯的 Agent 工具报错统计：

1. **第一优先级：用户的意图声明、方向纠偏与亲自补救信号**——直接反映用户的目标排序、判断品味、授权边界与被迫迁就。
2. **第二优先级：授权项目仓库内的真实工作产出与演进**——用真实交付物、返工痕迹与手改差异检验流程是否真正帮到用户。
3. **第三优先级：跨 Agent 会话结构、派发协作与工具轨迹**——补充还原任务上下文、定位协作断层、核对配置加载与增量游标。

### 会话格式核对基准

2026-11-03 核对了 Pi 1.5.0 随包文档，以及下面的官方在线说明与上游源码；当时本机版本检查为 Codex CLI 0.163.0、Claude Code 2.1.312，另只查看了三者各一份现有记录的类型与字段结构，未复制私人会话内容：

- Pi：[会话格式](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/session-format.md)、[环境变量](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/environment-variables.md)。
- Codex：[配置与 CODEX_HOME](https://developers.openai.com/codex/config-advanced/)、[rollout 存储](https://github.com/openai/codex/blob/main/codex-rs/rollout/src/recorder.rs)、[会话来源与元数据](https://github.com/openai/codex/blob/main/codex-rs/protocol/src/protocol.rs)、[存储目录常量](https://github.com/openai/codex/blob/main/codex-rs/rollout/src/lib.rs)。
- Claude Code：[会话存储与导出](https://code.claude.com/docs/en/sessions)、[子代理记录](https://code.claude.com/docs/en/sub-agents)。官方明确 JSONL 内部格式会随版本变化。

在线文档与上游 `main` 不保证等于用户当前安装版本；本机抽样也不证明所有历史格式均已覆盖。每次先核对用户实际版本、存储设置和代表性记录，把所依据的版本、来源与缺口写入任务日志。不能因路径存在就认定记录完整，也不能用本文件的核对日期冒充本次查证。

## 1. 第一优先级：识别用户意图、纠偏与工具迁就信号

先确认消息确属**用户本人直接交互**（排除系统提示、技能展开、`tool_result`、自动续跑、子代理继承提示及演练合成材料），再重点识别五类高价值信号：

| 信号类型 | 典型表现 | 归类与后续动作 |
| --- | --- | --- |
| 明示规则与价值排序 | 用户主动声明“记住… / 以后一律… / 别再… / 先保住 X 再考虑 Y” | 提炼为 `CORE.md` 明示偏好候选；对话中明确要求长期记住的，经核对原话后可视同确认该原意 |
| 否定、打断与方向纠偏 | “不是这个意思”“别改这块”“停下，方向反了”“不要过度设计”，尤其同一会话或跨会话对同一方向纠偏 `≥2` 次 | 区分是用户核心标准尚未显式写出（入 `CORE.md` 候选），还是已有投影规则过长、冲突或未被宿主遵守 |
| 推翻重做与亲自接手 | Agent 交付后用户拒绝采纳、回退重来，或在会话间隙手改代码/文档修补同类问题 | 对照 Agent 原产出与用户最终保留版本的差异，提炼用户的真实完成标准与质量品味 |
| 重复搬运与手工绕行 | 每次开新会话或跨工具协作都要手动复制上下文、重复交代固定约束、手跑一串固定胶水步骤 | 归入 `CORE.md` 的 **`A<n>` 工具迁就清单**作为消除靶子，严禁当成“用户偏好”固化进指令（除非用户明示希望保留人工操作） |
| 顺畅放行与复用做法 | 某类需求澄清、拆解粒度、验证证据或交付表达被用户一次接受并反复沿用 | 记为值得保持或跨工具推广的有效工作法，不无故折腾替换 |

**提炼与锚点拾取边界**：

- 只提炼可观察的工作要求（目标取舍、质量标准、拆解与验证方式、授权与精力边界），**严禁推断人格、性格、情绪或心理动机**。
- 单次偶然观察只记入当次 `log.md`；“观察习惯”必须具备至少 2 个跨轮或跨会话的独立事件指针，才能提议写入 `CORE.md` 待确认候选区。
- **拾取 `[Jianhe 待落盘]` 锚点**：在读取会话范围时同步检索 `[Jianhe 待落盘]` 前缀线索（这是投影轻约定留下的会话线索，不是日志记录）。须结合上下文核实确有用户本人同意记录的原话，再与当前 `CORE.md` 中已确认、待确认候选及已拒绝条目比对去重；未重复时按完整两层记录与写入门禁落盘至 `CORE.md`“待确认候选”区（锚点不直接视为正文已确认核心），并在候选的“证据与提出”字段记录锚点所在会话指针以防后续重复处理，绝不修改原会话文件。

## 2. 第二优先级：授权项目仓库与宿主现场的有界核查

会话只记录“说了什么、调了什么”，项目产物才反映“最终留下了什么”。在严格遵守权限边界的前提下做有界只读核查：

- **授权范围硬边界**：只读取当前工作目录、用户本次明确指定的项目路径、已登记在 `.jianhe/assets/` 的受管配置路径，或当前分析会话中用户明确授权工作的仓库。**严禁全盘搜索用户主目录或读取无关私人项目**；仓库不可访问或未获授权时标为未核查缺口。
- **有界采样重点**（围绕当前复盘或验证目标按需抽查，不遍历全仓历史）：
  1. **近期提交演进与返工痕迹**：查看相关时间窗口内的 `git log` 与关键提交说明，识别哪些交付一次稳妥落地、哪些紧接着出现修复返工或用户手动修正提交。
  2. **项目级约定与验收载体**：按需查看项目内 `AGENTS.md` / `CLAUDE.md`、`README.md`、`REVIEW.md` 或本地可见的设计/验收记录，理解用户在真实项目里执行的质量门槛与领域工作法。
  3. **宿主配置与投影现场差异**：比对宿主实际加载的指令/配置文件与 `.jianhe/CORE.md`、`assets/<名字>/README.md` 映射表，捕获用户手改内容（区分跨工具通用要求与单宿主局部参数适配）。
- **隐私与最小摘录**：只记录文件路径、提交哈希或配置节标题及必要的短差异说明，绝不把业务机密、凭证值或大段项目源码复制进 `.jianhe/logs/` 或用于外部检索。

## 3. 第三优先级：跨 Agent 会话定位与结构解析

### 3.1 找到本次会话来源

先使用用户提供的位置、已有日志或宿主可用的只读会话接口，再检查相关 Host 的实际设置与默认位置。只在已授权范围中发现文件，不为找记录读取认证凭证文件。

| Host | 默认候选入口 | 需要核对的覆盖情况 |
| --- | --- | --- |
| Pi | `~/.pi/agent/sessions/` 中的 JSONL | `PI_CODING_AGENT_DIR`、`PI_CODING_AGENT_SESSION_DIR` 或启动参数可能改变位置；`--no-session` 不保存。当前持久会话可由 `PI_SESSION_FILE` 提供路径 |
| Codex | `CODEX_HOME`，默认 `~/.codex`；重点核对 `sessions/`，历史范围需要时检查 `archived_sessions/` | 先确认实际用户目录与记录模式。`history.jsonl` 不能未经核对就当成含完整工具执行的会话记录；临时会话或未落盘部分可能不可获取 |
| Claude Code | `~/.claude/projects/<项目目录>/<会话>.jsonl` | `CLAUDE_CONFIG_DIR` 可改变根目录；项目目录名可能编码或自定义，不从名称猜实际项目。保留时间、清理和禁止写入的设置会影响覆盖 |

Windows 原生环境使用实际用户目录；WSL 的 Linux HOME 与 Windows 用户目录分开处理，不默认为同一份历史。目录不存在时区分未使用、位置自定义、未保留和无法访问，不能直接报告“没有问题”。

对每个来源记录：Host/版本、实际位置、项目或会话标识、本次起止范围、发现的文件/会话、未覆盖的原因。目录数量、文件修改时间和文件名时间只辅助定位，不代替事件范围核对。当前正在运行 Jianhe 生成的日志不计入用户日常习惯样本。

### 3.2 理解记录，不把外层角色当真人身份

- **Pi**：
  - 文件头 `type=session` 描述 `id`、`cwd`、`version` 等。普通条目有 `id`、`parentId`、`timestamp`；消息在 `type=message` 的 `message` 中，核对 `role` 和内容块。
  - `parentSession` 可来自 `/fork`、`/clone`，**单凭它不能判为子代理**。条目也能在同一文件内形成分支；回看特定任务时沿父子关系理解上下文，不把所有分支拼成一条直线。
  - `custom_message`、系统消息、技能展开和运行时通知不等于用户原话。助手的 `toolCall` 与 `toolResult` 按调用标识关联，不把工具结果重复描述算成新执行。
  - `compaction`、`branch_summary` 是摘要而非新的用户行为。不同版本可能没有完整系统提示记录；未看到不等于没有加载。
- **Codex**：
  - 先看 `session_meta` 的 `payload`，核对会话/线程标识、工作目录、版本及来源。`source`、`thread_source`、父线程或分叉信息是分类线索，须结合实际版本和关联记录判断。
  - 已核对的记录形状包括 `response_item`、`event_msg`、`turn_context`、`compacted` 等。消息角色与内容位于内部 `payload`；工具调用和结果通过 `call_id` 等标识关联。
  - 同一用户消息或工具事件可能在不同记录类型中出现，按事件/轮次/调用身份去重，不把展示副本再次计数。`role=user` 可能是注入指令或上下文，不能一律当真人表达。
  - `source=exec` 只说明启动入口，不足以断言是定时任务；子代理来源也不是真人习惯证据。计费、用量、推理或状态记录不当作用户消息，不把它们的数字直接累加成指标。
- **Claude Code**：
  - 优先使用已可获取的会话导出或只读接口；原始 JSONL 需按当前版本核对。不要为了导出历史发起新的 `claude -p` 模型请求。
  - 可见形状包括 `type=user/assistant/system`、嵌套 `message.role/content`、会话标识及消息 `uuid`。相同消息身份的多行或请求快照可能只是同一消息的不同表示，不能逐行算独立事件。
  - `type=user` 中可能包含 `tool_result`、系统注入、压缩摘要或元信息，须结合字段、内容类型和上下文区分用户文本与工具结果，不因出现 `user` 角色就当成偏好或批准。
  - 子代理可在 `<sessionId>/subagents/agent-<agentId>.jsonl` 中。路径、代理标识、`isSidechain` 等连同父任务和派发记录一起判断；继承指令和主会话摘要不重复算成新用户要求。

### 3.3 会话与事件性质分类及去重

按实际证据注明会话或事件性质，混合会话不必强求单一标签：

| 性质 | 怎样用于分析 |
| --- | --- |
| 用户直接交互 | 可支持明确偏好、反复纠偏、亲自补救与工作法判断；仍须核对原文与上下文 |
| 子代理执行 | 用于判断多 Agent 分工、派发交接与执行质量，尽量关联父任务；其任务提示和继承历史不算用户再次表达 |
| 自动任务 | 用于判断定时或自动续跑表现，不能把自动唤醒或守护提示当成用户不断催促 |
| 演练或合成材料 | 单独说明验证范围，绝不混入真实用户习惯、真实问题频率或收益证据 |
| 来源性质未知 | 说明缺失信息，不强行归为真人、自动或子代理，也不静默丢弃 |

同一会话的重复导出用会话与事件身份、内容位置及可核对继承关系关联，保留一个主证据并列出副本。分叉前继承的事件不重复计为新发生；分叉后的不同操作保留。相同措辞出现在不同独立事件中（例如用户真的在不同会话里两次手动纠偏同一问题），正是重要的跨事件证据，不能仅凭文本相似删除。

## 4. 分批读取、增量游标续接与引证

1. **确定起点与截止点**：固定本次截止时间，读相关旧日志中的覆盖记录；首次使用明确起点。时间条件用于范围判断，不是唯一续接依据。
2. **保留精确游标**：记录每个会话来源已处理到的文件位置与末条事件 ID（使用行号时同时保留会话标识与末条标识，不只存一个全局日期）；对抽查过的授权项目仓库记录仓库路径与核对到的最新 commit 或时间范围。再次调用先核对原位置仍可定位。
3. **处理同秒新事件与补导入历史**：本轮重新发现范围内的来源与新增位置。**与上次最后记录时间相同的新事件仍要处理**；文件中新增的旧时点记录或导入历史须注明其真实事件时间与新增来源性质，不伪装成当前时段发生。
4. **按批及时记账**：按可处理批次读取，先看元信息和必要上下文，再按“用户信号 → 项目产出 → 工具协作”分析范围内事件。每批结束及时记入覆盖、分类、关联副本、关键发现和未读部分。搜索只用于定位候选，未命中不等于已读完全部内容。
5. **摘要与游标异常**：分支或压缩摘要可辅助定位，但不代替原始证据；回看旧上下文注明用途，不重复计为新处理事件。来源被清理或改写导致旧游标失效时，如实报告缺口并说明重核范围，不悄悄跳到文件末尾。
6. **诚实标注未覆盖**：文件有内容但格式未识别、行未读完或仓库未授权读取时，记为未覆盖及原因。抽样或局部定向排查只交付对应范围结论，不称为完整扫描，也不推进全面扫描游标。
7. **交付覆盖表与脱敏引证**：完成或中断时交付来源覆盖表（记录来源位置、本次范围、实际读取位置/末条标识、已识别性质/副本关系、未读原因、下次续接点）。证据引用注明 Host/仓库、会话或提交标识、事件 ID/行号及时间；只保留支持判断的必要短摘录，剥离无关账号、私人标识、凭证值和大段工具输出，不读或抄模型内部逐字推理。

## 5. 本次运行轨迹与历史样本隔离

正在分析的历史材料与本次运行 Jianhe 的宿主原生轨迹属于不同层次，不把本次分析或演练操作混入用户习惯统计。

- Pi 的 `PI_SESSION_FILE`、`PI_SESSION_ID` 可提供当前运行会话线索，先核对文件头或元信息确与本次运行一致，再按需核对工具调用与结果；其他宿主只使用本次会话明确提供的路径、标识或只读导出，不凭相似文件名猜测。
- 只将已核实的身份、位置、覆盖范围与留存条件写入本次 `log.md`。未暴露路径、无法读回或来源不完整时标明“未取得/未核验”，不自动修改宿主日志设置；当前会话文件仍在追加时，分开说明已核对到的位置与后续操作；由他人提供的轨迹注明提供者。
- 原生轨迹用于核对动作，不能代替用户对 `CORE.md` 或配置修改的具体批准，也不能证明尚未在真实任务中观察到的工作收益。
