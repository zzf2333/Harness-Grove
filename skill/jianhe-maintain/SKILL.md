# 体验验证、收敛剪枝与双向对齐

## 目的与设计理由

在 Jianhe 中，**人是唯一主体**，所有 Agent 配置与协作流都只是服务用户内在核心的可替换投影。一套健康的用户级 Harness 必须**能长也能剪**：没有退场机制的优化只会堆积成没人看的规则坟场。本入口回答：已落地的方案真的让用户工作更顺畅了吗？哪些值得固化毕业，哪些应当精简或撤回？宿主现场的手改说明用户核心有了什么新演进？Jianhe 自身是否在帮倒忙？

“文件还在、没报错、用户没投诉”绝不等于有效；换模型或工具升级后，旧补丁更可能变成冗余负担。依靠宿主已有的读取、搜索、文档查询、编辑与执行能力独立完成评估与获准维护，不依赖项目 CLI 或其他 Skill。

## 1. 建立日志、定位待结算项与识别旧版积压

读取请求后，按 [用户核心、跨工具投影与操作契约](./references/contract.md) 第 2 节确定四级日志位置并核实可取得的本次宿主轨迹线索，新建本次 `log.md` 并链接原方案日志（同次任务接续则共用原日志）。

- **读取核心与看板全局**：分批读取 `CORE.md`、根 `README.md` 的 `在验证` 与 `待决定` 双池看板、`assets/<名字>/README.md` 映射表及关联日志尾部；遇到 `v0.0.3` 遗留目录时，按 [contract.md](./references/contract.md) 1.5 节将未分诊旧项归入“旧版待跟进（待分诊）”分批处理，不删旧历史。
- **读回原立项契约**：逐项核对原日志 `#p<n>` 中的服务锚点（`C<n>`/`A<n>`）、期望的用户可感知正信号、反向代价、基线口径、到期条件、当时批准范围与 `backups/` 恢复依据。无历史记录的存量配置从现场与用户说明重建已知部分，缺失初衷如实标明，不把普通存量配置冒充本产品历史成果。

## 2. 核查用户真实体验、项目产出与工具能力变化

遵循 [用户信号、项目产出与跨 Agent 记录读取](./references/signal-reading.md) 分批采集后续证据（允许跨扫描窗口回看原依据，区分真人交互、子代理、自动任务与演练合成材料）：

- **对照人侧信号与项目交付**：查看后续真实任务中用户的方向纠偏、手工补救、等待与交接往返是否减少，授权项目仓库内的交付演进与一次验收表现是否改善，以及 `CORE.md` 中的目标或偏好是否已变化。
- **严守可比性与归因边界**：涉及指标时按 [contract.md](./references/contract.md) 第 4 节复核原口径、窗口与 `n/N` 有效机会。确认 `N=0` 无相关任务机会时效果保持**未知**（禁写 `0%`）；模型更换或任务类型变化时如实描述观察值变化并注明归因限制，不把伴随变化硬算成优化功劳。
- **重核工具原生演进**：核查相关宿主当前版本官方文档与本地配置，识别原先复杂的提示词补丁、脚本或外部组件是否已被宿主新原生能力更简单地覆盖，不因沉没成本硬保过时方案。

## 3. 逐项强制收敛、剪枝与旧项分诊

在 `log.md` 按 **[contract.md](./references/contract.md) 第 4 节四段式（观察事实 → 可比性与限制 → 对原预测的支持程度 → 下一步处置）** 形成判断，执行有界收敛：

| 处置动作 | 触发依据与看板流转 |
| --- | --- |
| **毕业留存** | 已有真实正向用户/项目证据且维护负担可控 → 固化为常规投影，从 `在验证` 移出结项，对应 `A<n>` 标为`已消除` |
| **精简 / 三方撤回** | **到期且有任务机会但无正向证据**、增加等待/维护负担、或已被原生能力覆盖 → **默认提议删减合并或撤回**，获批执行后结项释放槽位 |
| **调整或替换** | 核心目标仍在但原做法水土不服 → 说明切换代价，获批调整或衔接 `jianhe-improve` 新立替代项（旧项标明被替代） |
| **有条件延期（限 1 次）** | 仅限确认 `N=0` 尚无相关任务机会或关键外部变动干扰判断 → 写明具体触发条件，**最多延期一次**，到期仍无证据则转入精简/撤回 |

对 `v0.0.3`“旧版待跟进”按批次分诊：已明显奏效的毕业结项；仍需观察且服务明确核心的补齐四要素并在 `在验证 ≤5` 容量内入池；纯工具参数折腾或长期无证据的提议归档结束或精简撤回。

## 4. 双向漂移对齐与三方比对安全执行

对照 `CORE.md`、`assets/` 映射表与各宿主原位文件（含逐字比对宿主共享 `AGENTS.md` 中的投影轻约定与 [contract.md](./references/contract.md) 1.4 节当前文本），按 [contract.md](./references/contract.md) 1.2 节 **5 步顺序**处置漂移：

- 双端同时修改冲突保留两端并列询问；宿主侧单向跨工具通用手改提议**反向吸收**进 `CORE.md` 确认后再按需同步其他宿主；单宿主专属参数登记为“工具局部适配”；核心已修订/撤回导致下游滞后（或轻约定复盘日期过期）列出差异请求批准同步；`v0.0.3` 历史未溯源条目先分类归属，不因未溯源直接提议删除。
- **获准执行与三方恢复**：讨论处置不等于授权。任何修改、删除、轻约定安装/日期更新或恢复，均须按 [contract.md](./references/contract.md) 第 2、3 节先记方案与批准、准备可读恢复依据；执行**撤回/恢复**时必须三方比对**原改前、当时实际改后、当前现场**，只生成撤回原项的反向差异并完整保留后续其他手改，同一片段冲突或依据不全时立即暂停报告，严禁拿旧备份整份覆盖。

## 5. Jianhe 元自评、更新看板与交付

每轮维护收尾必须包含一小节诚实的 **Jianhe 元自评**：检查近期提出的建议有多少被用户采纳、多少真正毕业留存、多少因无证据或增负被撤回，以及近期记录是否滑向“脱离 `C<n>`/`A<n>` 的纯 Agent 参数折腾”；发现偏航或打扰过多时，主动建议精简资产、拉长复盘周期或调低看板在制上限。

获准操作读回核实后，同步更新 `CORE.md`、`assets/` 映射表、根 `README.md` 双池看板与下次建议复盘日（保留历史日志原预测不篡改），向用户交付：**逐项四段式结论与处置结果 → 双向漂移与 `CORE.md` 更新情况 → Jianhe 元自评 → 剩余未知与下次复盘日 → `log.md` 路径**。

## 不可妥协的九条硬底线

1. **人是唯一主体，防黑盒揣测**：`CORE.md` 只记可观察的工作要求，严禁推断人格、情绪或心理动机；观察习惯须有 `≥2` 个独立事件指针才提议候选；未经用户确认不建改 `CORE.md`，候选、已拒绝项与 `A<n>` 迁就严禁投影进宿主配置（[contract.md](./references/contract.md) 1.1 节）。
2. **迁就不当偏好固化**：因工具缺失或接口笨拙被迫重复的手工补救归入 `A<n>` 作为消除靶子，绝不当成用户偏好写进指令永久固化（除非用户明示希望保留人工操作）。
3. **有界在制防账本化**：活跃看板默认 `在验证 ≤5`、`待决定 ≤5`，不在根 `README.md` 建池外影子清单；`在验证` 满额阻塞新增复杂度方案（仅豁免纯删减、故障修复、三方恢复、漂移对齐与 `CORE.md` 确认）；到期无正向用户证据默认提议精简或撤回（[contract.md](./references/contract.md) 1.3 节）。
4. **日常零目录读写开销**：普通项目任务不读写 `.jianhe/`；可选投影轻约定只做收尾询问与输出 `[Jianhe 待落盘]` 会话锚点线索（线索不是记录或日志）或转交 Jianhe Skill，裸片段绝不直接写文件（[contract.md](./references/contract.md) 1.4 节）。
5. **两层记录与四级日志位置**：原生轨迹核对实际调用，Markdown 及时按批记证据、决策、批准与结果，禁拖到结束补写；日志位置按“本次明确指定 → 接续原日志 → 用户已明确设置的保存位置 → 默认 `.jianhe/logs/`”解析，写入失败或拒绝保存时暂停新的正式分析与修改，仅做必要只读状态核对并报告，恢复后先补明状态（[contract.md](./references/contract.md) 第 2 节）。
6. **写入前硬门禁**：任何 `CORE.md`、资产、宿主配置写入或第三方软件安装/卸载前，必先核对现场、在日志记清具体方案与用户本人批准原话/位置及范围、保存并读回确认可用的改前恢复依据；只读分析不顺手建资产或改环境说明（[contract.md](./references/contract.md) 第 2、3 节）。
7. **三方比对恢复与手改优先**：用户手改 `CORE.md` 或宿主配置永远优先，不为符合文档覆盖手改；撤回改动须三方比对“原改前 / 实际改后 / 当前现场”，只生成反向差异并保留后续修改，冲突或依据不足时暂停报告（[contract.md](./references/contract.md) 1.2、3 节）。
8. **诚实区分写入、加载与真实收益**：文件修改成功、宿主已加载、实际工作改善分开报告；`N=0` 无观察机会效果保持未知（禁写 `0%`），缺失不补零，不从 Token 推算实付费用，演练合成材料严格隔离（[contract.md](./references/contract.md) 第 4 节）。
9. **有界读取与隐私脱敏**：只读授权会话、当前/指定项目仓库与受管配置，不扫全盘无关私人目录；外部检索不上传私人会话、配置、源码或凭证值（[signal-reading.md](./references/signal-reading.md)）。
