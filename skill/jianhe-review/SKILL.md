# 用户核心识别、漂移核查与机会发现

## 目的与设计理由

在 Jianhe 中，**人是唯一主体**，所有 Agent（Pi、Codex、Claude Code 及未来工具）都只是围绕用户核心存在的可替换投影与执行器。本入口回答三个问题：用户真正在追求什么工作结果与标准？当前流程里哪些是真实偏好、哪些是被工具限制逼出来的迁就？现有跨工具投影是否偏离了用户的真实需要？

不能只统计 Agent 工具报错或等用户自己指出工具名：必须优先观察用户的意图表达、反复纠偏与真实项目产出，再结合现有及外部工具能力主动发现能减轻心智负担、提升交付质量的机会。依靠宿主已有的读取、搜索、文档查询与对话能力独立完成研究，不依赖项目 CLI 或其他 Skill。

## 1. 确定范围、建立日志与续接游标

读取请求后，按 [用户核心、跨工具投影与操作契约](./references/contract.md) 第 2 节确定四级日志位置并核实可取得的本次宿主原生轨迹线索，尽早建立或续写 `log.md`。

- **区分全面复盘与定向排查**：全面复盘覆盖授权可访问的信号来源，按 [用户信号、项目产出与跨 Agent 记录读取](./references/signal-reading.md) 第 4 节读取旧日志游标（核对会话文件位置与末条事件 ID，处理同时间戳新事件）；定向排查只聚焦目标问题，明确边界且不推进全面扫描游标。
- **续接既有看板与老目录**：按 [contract.md](./references/contract.md) 1.3、1.5 节分批读取根 `README.md` 的 `在验证`、`待决定` 看板（及 `v0.0.3` 遗留的“旧版待跟进”）与 `CORE.md`；索引缺失或受限时按相关日志尾部补查，检查暂缓重评条件是否满足。只询问影响本次判断的关键缺口，不要求用户先填环境调查表。

## 2. 按三级优先级读取真实工作信号

严格遵循 [signal-reading.md](./references/signal-reading.md) 分配注意力，每批只读处理后及时记录覆盖范围、来源性质分类（区分真人交互、子代理、自动任务、演练合成材料与未知来源）、去重关系及证据指针：

1. **第一优先级：用户的意图声明、方向纠偏与 `[Jianhe 待落盘]` 锚点**——重点捕获用户的“记住/以后一律”明示要求、连续否定与方向纠偏（尤其同向 `≥2` 次）、推翻重做及手工绕行。同步检索会话中的 `[Jianhe 待落盘]` 锚点线索（核实上下文确有用户本人同意原话，与当前 `CORE.md` 已确认、待确认候选及已拒绝条目比对去重；锚点仅代表同意记入待确认候选，落盘须走完整写入门禁并在“证据与提出”记录锚点会话指针，不改原会话）。
2. **第二优先级：授权项目仓库内的工作产出与演进**——在当前工作目录或用户明确授权的项目仓库内有界抽查近期提交演进、返工修补痕迹、项目级约定与验收记录，看流程最终留下了什么质量结果。
3. **第三优先级：跨 Agent 会话结构与协作轨迹**——还原多工具/子代理交接成本、重复背景搬运、验证断层与配置实际加载情况。需要定量基线时按 [contract.md](./references/contract.md) 第 4 节写清统计对象、窗口与 `n/N` 有效机会，不为每个问题强凑指标。

## 3. 提炼 `CORE.md` 候选、识别 `A<n>` 迁就并核查双向漂移

围绕具体工作场景梳理可读现状（目标结果、任务起点、人机分工、交接检查点与人工介入处），按 [contract.md](./references/contract.md) 1.1、1.2 节分离三类对象：

- **提炼 `C<n>` 核心候选与有效做法**：将明示规则或具 `≥2` 个独立事件证据的观察习惯整理为可观察的工作要求（目标排序、判断品味、领域工作法、授权与注意力边界）；识别反复顺畅奏效的做法建议保持或跨工具推广。只要求分析时不擅自建改 `CORE.md`，先记入 `log.md` 并在交付时列出候选确认单。
- **剥离 `A<n>` 工具迁就靶子**：将因上下文断裂、工具缺口或配置繁琐导致的重复手工搬运归为 `A<n>` 待消除迁就，绝不当成“用户习惯”提议写进长期指令。
- **核查 `CORE ↔ 投影 ↔ 宿主现场` 双向漂移**：对照 `CORE.md`、`assets/<名字>/README.md` 映射表与宿主原位文件，按 [contract.md](./references/contract.md) 1.2 节的 5 步顺序分类（双端冲突并列询问 → 单向通用手改提议反向吸收 → 单向局部参数登记适配 → 核心变更滞后或未确认泄漏提议同步 → 意图不明集中询问）。

## 4. 主动研究能力并比较有锚点的改进机会

从“服务哪条 `C<n>` 核心或消除哪条 `A<n>` 迁就”提出研究问题，既查现有工具未用好的原生能力，也查第三方实践：

- 核对当前版本官方文档、变更说明与本地可用前提，严格区分“宣称支持、当前版本支持、本地已启用、对这位用户真实有效”，记清来源、版本、核对日期与适用条件。
- 比较维持现状、调整工作步骤、用好已有能力、跨工具投影或引入新工具，考虑模型波动或任务差异等替代解释，不把所有摩擦都归因于“规则写得不够多”。
- 每个重要机会在 `log.md` 建立独立 `### P1`、`### P2` 条目，串起：**服务锚点（`C<n>`/`A<n>`）→ 观察证据 → 期望改善的用户可感知结果 → 查证能力与前提 → 建议改变的步骤 → 代价、反例与未知项 → 验证方式**。无值得改动之处就如实建议保持现状，不凑方案数量。

## 5. 有界交付、获准落盘与衔接

交付四部分清晰结论：**当前工作流与有效做法摘要 → `CORE.md` 候选确认单与 `A<n>` 迁就清单 → 双向漂移待决项 → 按核心价值排序的少量改进机会（含扫描/研究缺口与来源覆盖表）**，并告知 `log.md` 路径。

- **遵守看板容量**：按 [contract.md](./references/contract.md) 1.3 节在双池上限（默认 `在验证 ≤5`、`待决定 ≤5`）内同步根 `README.md` 看板；`待决定` 已满时，新机会作为未激活历史观察留存本次 `log.md` 并向用户并列展示，由用户取舍腾位后再入池。
- **获准确认或实施**：用户仅要求复盘分析时到此停止，不改环境。若用户当场确认 `CORE.md` 候选措辞，或委托继续选型/落地（可衔接 `jianhe-improve`，未安装时本入口也可独立完成），严格按 [contract.md](./references/contract.md) 第 1.1、2、3 节执行写入门禁、备份读回、映射同步与 `在验证` 四要素登记。

## 不可妥协的九条硬底线

1. **人是唯一主体，防黑盒揣测**：`CORE.md` 只记可观察的工作要求，严禁推断人格、情绪或心理动机；观察习惯须有 `≥2` 个独立事件指针才提议候选；未经用户确认不建改 `CORE.md`，候选、已拒绝项与 `A<n>` 迁就严禁投影进宿主配置（[contract.md](./references/contract.md) 1.1 节）。
2. **迁就不当偏好固化**：因工具缺失或接口笨拙被迫重复的手工补救归入 `A<n>` 作为消除靶子，绝不当成用户偏好写进指令永久固化（除非用户明示希望保留人工操作）。
3. **有界在制防账本化**：活跃看板默认 `在验证 ≤5`、`待决定 ≤5`，不在根 `README.md` 建池外影子清单；`在验证` 满额阻塞新增复杂度方案（仅豁免纯删减、故障修复、三方恢复、漂移对齐与 `CORE.md` 确认）；到期无正向用户证据默认提议精简或撤回（[contract.md](./references/contract.md) 1.3 节）。
4. **日常零目录读写开销**：普通项目任务不读写 `.jianhe/`；可选投影轻约定只做收尾询问与输出 `[Jianhe 待落盘]` 会话锚点线索（线索不是记录或日志）或转交 Jianhe Skill，裸片段绝不直接写文件（[contract.md](./references/contract.md) 1.4 节）。
5. **两层记录与四级日志位置**：原生轨迹核对实际调用，Markdown 及时按批记证据、决策、批准与结果，禁拖到结束补写；日志位置按“本次明确指定 → 接续原日志 → 用户已明确设置的保存位置 → 默认 `.jianhe/logs/`”解析，写入失败或拒绝保存时暂停新的正式分析与修改，仅做必要只读状态核对并报告，恢复后先补明状态（[contract.md](./references/contract.md) 第 2 节）。
6. **写入前硬门禁**：任何 `CORE.md`、资产、宿主配置写入或第三方软件安装/卸载前，必先核对现场、在日志记清具体方案与用户本人批准原话/位置及范围、保存并读回确认可用的改前恢复依据；只读分析不顺手建资产或改环境说明（[contract.md](./references/contract.md) 第 2、3 节）。
7. **三方比对恢复与手改优先**：用户手改 `CORE.md` 或宿主配置永远优先，不为符合文档覆盖手改；撤回改动须三方比对“原改前 / 实际改后 / 当前现场”，只生成反向差异并保留后续修改，冲突或依据不足时暂停报告（[contract.md](./references/contract.md) 1.2、3 节）。
8. **诚实区分写入、加载与真实收益**：文件修改成功、宿主已加载、实际工作改善分开报告；`N=0` 无观察机会效果保持未知（禁写 `0%`），缺失不补零，不从 Token 推算实付费用，演练合成材料严格隔离（[contract.md](./references/contract.md) 第 4 节）。
9. **有界读取与隐私脱敏**：只读授权会话、当前/指定项目仓库与受管配置，不扫全盘无关私人目录；外部检索不上传私人会话、配置、源码或凭证值（[signal-reading.md](./references/signal-reading.md)）。
