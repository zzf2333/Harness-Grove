# 跨 Agent 使用记录读取

这是读取指导，不是解析器或固定格式协议。使用宿主已有的文件、搜索或已提供的只读会话接口；不运行额外模型会话来“重建历史”，不安装采集工具，不改写原始记录。

## 核对依据与适用范围

2026-11-03 核对了 Pi 1.5.0 随包文档，以及下面的官方在线说明与上游源码；本机版本检查为 Codex CLI 0.163.0、Claude Code 2.1.312。另只查看了三者各一份现有记录的类型与字段结构，没有复制私人会话内容。

- Pi：[会话格式](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/session-format.md)、[环境变量](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/environment-variables.md)。
- Codex：[配置与 CODEX_HOME](https://developers.openai.com/codex/config-advanced/)、[rollout 存储](https://github.com/openai/codex/blob/main/codex-rs/rollout/src/recorder.rs)、[会话来源与元数据](https://github.com/openai/codex/blob/main/codex-rs/protocol/src/protocol.rs)、[存储目录常量](https://github.com/openai/codex/blob/main/codex-rs/rollout/src/lib.rs)。
- Claude Code：[会话存储与导出](https://code.claude.com/docs/en/sessions)、[子代理记录](https://code.claude.com/docs/en/sub-agents)。官方明确 JSONL 内部格式会随版本变化。

这些在线链接会更新，上游 `main` 不保证等于用户安装版本；本机抽样也不证明所有历史格式都已覆盖。每次先核对用户实际版本、存储设置和代表性记录，把所依据的版本、来源与缺口写入任务日志。不能因为路径存在就认定记录完整，也不能用本文件的核对日期冒充本次查证。

## 1. 找到本次来源

先使用用户提供的位置、已有日志或宿主可用的只读会话接口，再检查相关 Host 的实际设置与默认位置。只在已授权范围中发现文件，不把整个用户目录当默认搜索范围。

| Host | 默认候选入口 | 需要核对的覆盖情况 |
|---|---|---|
| Pi | `~/.pi/agent/sessions/` 中的 JSONL | `PI_CODING_AGENT_DIR`、`PI_CODING_AGENT_SESSION_DIR` 或启动参数可能改变位置；`--no-session` 不保存。当前持久会话可由 `PI_SESSION_FILE` 提供路径 |
| Codex | `CODEX_HOME`，默认 `~/.codex`；重点核对 `sessions/`，历史范围需要时检查 `archived_sessions/` | 先确认实际用户目录与记录模式。`history.jsonl` 不能未经核对就当成含完整工具执行的会话记录；临时会话或未落盘部分可能不可获取 |
| Claude Code | `~/.claude/projects/<项目目录>/<会话>.jsonl` | `CLAUDE_CONFIG_DIR` 可改变根目录；项目目录名可能编码或自定义，不从名称猜实际项目。保留时间、清理和禁止写入的设置会影响覆盖 |

Windows 原生环境使用实际用户目录；WSL 的 Linux HOME 与 Windows 用户目录分开处理，不默认为同一份历史。只读取定位所需的设置，不为找记录读取认证文件。目录不存在时区分未使用、位置自定义、未保留和无法访问；不能直接报告“没有问题”。

对每个来源记录：Host/版本、实际位置、项目或会话标识、本次起止范围、发现的文件/会话、未覆盖的原因。目录数量、文件修改时间和文件名时间只能帮助定位，不代替事件范围核对。当前任务正在生成的日志不进入本次用户习惯样本。

## 2. 理解记录，不把外层类型当真人身份

### Pi

- 文件头 `type=session` 描述 `id`、`cwd`、`version` 等。普通条目有 `id`、`parentId`、`timestamp`；消息在 `type=message` 的 `message` 中，核对 `role` 和内容块。
- `parentSession` 可来自 `/fork`、`/clone`，**单凭它不能判为子代理**。条目也能在同一文件内形成分支。回看特定任务时沿父子关系理解上下文，不把所有分支拼成一条线。
- `custom_message`、系统消息、技能展开和运行时通知不等于用户原话。助手的 `toolCall` 与 `toolResult` 应按调用标识关联；不要把工具结果重复描述算成新执行。
- `compaction`、`branch_summary` 是摘要，不是新的用户行为。不同版本可能没有完整系统提示记录；未看到不等于没有加载。

### Codex

- 先看 `session_meta` 的 `payload`，核对会话/线程标识、工作目录、版本及来源。`source`、`thread_source`、父线程或分叉信息是分类线索，必须结合实际版本和关联记录。
- 已核对的记录形状包括 `response_item`、`event_msg`、`turn_context`、`compacted` 等。消息角色与内容位于内部 `payload`；工具调用和结果可通过 `call_id` 等标识关联。
- 同一用户消息或工具事件可能在不同记录类型中出现。根据事件/轮次/调用身份和上下文建立关联，不把展示副本再次计数。`role=user` 的内容可能是注入的指令或上下文；不能一律当真人表达。
- `source=exec` 只说明启动入口，不足以断言是定时任务；子代理来源也不是真人习惯证据。计费、用量、推理或状态记录不当作用户消息；本片不把它们的数字直接累加成指标。

### Claude Code

- 优先使用已经可获取的会话导出或只读接口；原始 JSONL 需要按当前版本核对。不要为了导出历史发起一个新的 `claude -p` 模型请求。
- 可见形状包括 `type=user/assistant/system`、嵌套 `message.role/content`、会话标识及消息 `uuid`。相同消息身份的多行或请求快照可能只是同一消息的其他表示，不能逐行算独立事件。
- `type=user` 中可能包含 `tool_result`、系统注入、压缩摘要或元信息。结合字段、内容类型和上下文区分用户文本与工具结果；不因为出现“用户”角色就接受其为偏好或批准。
- 子代理可在 `<sessionId>/subagents/agent-<agentId>.jsonl` 中。路径、代理标识、`isSidechain` 等只作核对线索，连同父任务和派发记录判断；不把继承的指令和主会话摘要重复算成新用户要求。

## 3. 分类与关联

按实际证据为会话或事件注明性质，不必强迫混合会话只有一种标签：

| 性质 | 怎样用于分析 |
|---|---|
| 用户直接交互 | 可以支持使用习惯、明确偏好和反复纠正的判断；仍需原文与上下文 |
| 子代理执行 | 用于判断协作、派发与结果，尽量关联父任务；其任务提示和继承历史不算用户再次表达 |
| 自动任务 | 用于判断自动流程表现，不能把自动续跑或定时提示当用户不断催促 |
| 演练或合成材料 | 单独说明验证范围，不混入真实习惯、真实问题频率或收益证据 |
| 来源性质未知 | 说明缺什么，不强行归为真人、自动或子代理，也不静默丢弃 |

以来源元数据、派发关系、任务说明及实际上下文判断。临时目录、`parentSession`、`exec` 或一句自动提示都不足以单独确定性质。不要一律排除所有子代理：它们可能正是理解工具协作所需的证据。

同一会话的重复导出用会话与事件身份、内容位置及可核对的继承关系关联，保留一个主证据并列出副本。分叉前继承的事件不重复计为新发生；分叉后的不同操作保留。相同措辞出现在不同独立事件中不能仅凭文本相似就删除。

## 4. 分批读取与增量续接

1. 固定本次截止时间，读相关旧日志中的覆盖记录；首次使用明确起点。时间条件用于范围判断，不是唯一续接依据。
2. 记录每个来源已处理到的会话、文件位置与可用事件 ID。使用行号时保留对应会话及末条标识，避免只保存一个全局日期。再次调用先核对原位置仍可定位。
3. 本轮重新发现范围内的来源与新增位置。**与上次最后记录时间相同的新事件仍要处理**；文件中新增的旧时点记录或导入历史要说明其事件时间和新增来源性质，不伪装成当前时段发生。
4. 按实际可处理的批次读取，先看元信息和必要上下文，再分析本次范围内事件。每批结束及时记覆盖、分类、关联副本、发现和未读部分。搜索只定位候选；没有命中不等于已经阅读全部内容。
5. 分支或压缩摘要可帮助定位，但不代替原始证据。读取历史上下文时注明用途，不能再次推进为新的已处理事件。来源改变导致旧位置无法可靠定位时，报告缺口并明确重新核对范围，不悄悄跳到文件末尾。
6. 文件有内容但无法识别消息、行未读完或格式不同，记录为未覆盖及原因。一次只读一部分就交付部分结果，不把抽样或摘要称为完整扫描。
7. 完成或中断时交付来源覆盖表。缺失来源保留原进度，定向分析不推进全面扫描进度；下次继续其未读部分，不依赖用户记住。

覆盖表可用以下列，不要求固定机读格式：

| 来源及会话 | 本次范围 | 实际读取位置与末条标识 | 已识别性质/副本关系 | 未读部分与原因 | 下次从哪里继续 |
|---|---|---|---|---|---|
| 文件或导出位置 | 起点至截止时间 | 行号/事件ID，或无法定位 | 根据实际记录说明 | 无内容、缺文件、未完成等 | 具体位置或待核实条件 |

## 5. 引证与交付

建议引用 Host、会话标识、文件或导出位置、事件 ID 或行号及时间；只保存支持判断的必要短摘录，去掉无关账号、私人标识、凭证值和大段工具输出。原文保留在原来源，不拷进项目仓库或外部查询。

没有可用原文或导出只包含一部分内容时，明确证据层次。日志中的说法不能证明实际读取顺序；核验时可对照宿主已有工具轨迹。不要读取或记录模型内部逐字推理来替代操作与决策依据。

交付实际覆盖、分类依据、关联与去重范围、候选及证据、未完成事项和下一步。达到当前决定所需证据就结束该判断；未完成的全面读取仍要明确保留缺口。纯 Skill 不能保证所有版本格式都能读取，也不自动保证全量捕获。

## 6. 本次操作轨迹与决策日志

正在分析的历史材料与本次执行的原生轨迹是两种来源，不把本次演练或自动执行混成用户习惯。原生轨迹可以核对工具实际调用和结果，Markdown解释依据、取舍、批准及结论；只读材料允许按批及时记录，补记须写明真实顺序，不能把后来知道的信息说成启动时已知。

Pi 的 `PI_SESSION_FILE`、`PI_SESSION_ID` 可提供当前会话线索，先确认文件头或会话元信息与本次运行对应，再按需核对工具调用和结果。其他宿主使用本次会话明确提供的路径、标识或只读导出，不根据相似文件名猜测，也不扫描不相关的私人会话。

只把已核对的身份、位置、覆盖范围和留存条件写进Markdown。没有暴露路径、无法读回或来源不完整时明确标未取得/未核验；不自动打开Host日志设置。当前文件可能仍在追加，核对到的位置与之后尚未核对的操作分开说明；有路径不保证完整或长期留存。若轨迹由验收者或其他人提供，记录提供者，不能冒称执行者自行取得。

不复制整份原生会话、凭证或内部推理到日志。配置、资产内容或安装等改变前，Markdown仍须先记录具体方案、对应批准和恢复依据；原生轨迹不能代替授权，也不能证明尚未观察到的收益。
