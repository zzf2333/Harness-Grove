# M-1 评测可行性探针协议

**版本：** v0.5 · 2026-10-28
**状态：** 待执行。本文和 [`examples/m-1/proposal.template.json`](../examples/m-1/proposal.template.json) 都是预注册设计。**还没有运行任何真实 Agent，也没有实测数据。**
**上位文档：** [PHE 产品与架构规范](PHE_SPEC.md)。术语、生命周期和放弃 L2 主张的出口都以规范为准。

M-1 只回答一个问题：**在一个重建出来的真实历史任务上，受控对照实验能否以可接受的成本识别出人为构造的规则差异？** 回答是 go、pivot 或 invalid_run。M-1 不回答某条真实规则该不该删。

本文中的门槛是本项目选定的**工程准入门槛**，不是统计显著性检验。用户可以在冻结前批准另一套数值；一旦冻结，就不能根据结果修改同一个实验。

---

## 1. 整体流程

```text
前置检查（不调用模型） → spike-000 用量测量（最多 2 次调用）
    → 填写并冻结 spike-001 proposal → 用户批准
    → 25 次正式运行 → 按固定顺序判定 → 报告
```

M-1 需要一个**最小 Runner**：隔离配置、按冻结的顺序启动 Target、调用外置验收器、记录用量和停止原因。它不是纯手工实验。M-1 之前不搭 SQLite、完整 Schema、自动 Reasoner 或多平台 Runner。

## 2. 路径与权限

必须给出两个绝对路径：`PHE_REPO` 是 Harness Grove 开发仓库；`TARGET_REPO` 是真实任务所在的仓库。两者必须是不同的目录，不能互相包含。不能默认把“当前仓库”当作其中任何一个。

| 路径 | 允许做什么 |
|---|---|
| `${PHE_REPO}/experiments/spike-00N/` | 唯一的持久实验产物目录。已被 `.gitignore` 忽略；提交脱敏样本需要用户另行批准 |
| `${TARGET_REPO}` | 只读：获取请求、起点快照和配置。不 reset、不 checkout、不装依赖、不新增文件 |
| `${TMPDIR}/phe-spike-00N-*/` | 一次性基线仓库，以及每次运行的新 worktree、隔离配置和临时依赖 |
| `~/.phe/` | M1 以后的部署目录。M-1 禁止写入 |

隔离要求：

- 先从任务起点快照建一个**只含这个起点的一次性 Git 仓库**，再在里面创建临时 worktree。不在源仓库执行 `git worktree add`，以免改动它的 `.git` 元数据。
- 不让实验 Agent 看到将来的修复提交、正确答案 Patch、其他组的日志或整份 proposal。
- 每个配置的临时初始提交只包含该组的最终配置，不能通过 `git show HEAD`、父提交或相邻目录拿回已删除的规则。各组的基线 Hash 分别记录。
- worktree 本身不是权限沙箱。只开放任务需要的读写和终端工具，并限制文件系统和网络访问。

## 3. Target：只固定 Claude Code

**Target = Claude Code。用量适配器 = `claude_result_modelUsage_v1`。** Codex、Claude Code 或 Pi 都可以作为 Host 来编排探针。这只是 M-1 的选择，不代表项目永久绑定 Claude。

- 用 `claude -p --output-format json` 的新会话模式。冻结实际的 CLI 版本、可执行文件 Hash、服务提供方、完整模型 ID、推理设置、参数和权限配置。[S1][S2]
- 不能只写 `sonnet` 这类会变的别名。不用 resume、模型 fallback、子 Agent 或自动重试。服务端的权重修订号拿不到时记为 `unknown`，不假装云端内部实现已被完全固定。
- 在隔离的用户配置和文件系统里，按原来的作用范围加载冻结的 `CLAUDE.md` 和必要的引用，并核对加载来源。不继承未冻结的个人记忆、插件、Hooks 或 MCP。每次运行都恢复同一份配置快照。
- **不用 `--bare`。** 它会跳过 `CLAUDE.md` 的自动发现，就不再是原生加载的实验了。[S2]
- **认证方式要先探测。** 不用 `--bare` 时，`claude -p` 会加载 `~/.claude` 下的配置，所以必须换到隔离的配置目录。换了目录后，订阅登录可能不可用，可能只能用 `ANTHROPIC_API_KEY` 按量计费。这一点由 spike-000 确认；如果属实，必须在预算审批时向用户说明。认证只保存引用，密钥不写进实验文档或日志。

加载链无法核实时，结果为 `pivot(load_chain_unknown)`；隔离无法落实时，结果为 `pivot(isolation_unavailable)`。这些都发生在正式运行之前，不算 `invalid_run`。

## 4. 前置检查（不调用模型）

在任何付费调用之前，完成以下检查：

- 起点快照独立重建 3 次，文件清单 Hash **3 次都一致**；依赖、构建过程和验收入口都可以固定。
- 外置的真实任务验收器对未修复的起点 **3 次都判失败**，对人工确认过的已修复版本 **3 次都判通过**。这检验的是验收器有没有测到任务本身，而不只是检查已有的 CI。
- 校准回执验收器对缺失回执、错误回执和正确回执，**每类 3 次都判断正确**。验收器和期望值不能被实验 Agent 读取或写入。真实验收在外置的可信副本上运行，不以 Agent 改过的测试文件为准。

真实任务缺少请求、起点或可用的验收器时，结果为 `pivot(historical_task_not_reconstructable)`。可以另立前瞻性的 Fixture 实验，但不能沿用当前的实验 ID 冒充历史任务复现。

## 5. 规则与对照

### 5.1 一条真实规则，两条人工控制

保留一条效果未知、非安全关键的真实规则 `R_real`，另外构造两条只用于探针的规则：

**必要信息控制 `C_required`**：规则里给出一个新生成的 128 位随机回执值，要求完成任务后在临时工作区写入 `.phe-calibration-receipt`。这个值不出现在原始需求、代码、历史、可见的验收器或文件名里。外置验收器检查两件事：真实任务通过，回执完全匹配。

- 这条规则只对**人工校准契约**是必要的，不声称它对真实业务必要。删掉它就是一个明确的信息缺失，用来检查规则内容有没有传到 Agent，以及验收器能不能发现差异。
- 随机值在一次实验里固定。每次运行相互隔离，不能从其他组读到这个值。

**冗余控制 `C_redundant`**：复制一句已经存在、与本任务无关且没有冲突的普通句子。删掉新增的这一句后，原句仍然在。不能复制 `R_real`、回执规则或安全规则。Diff 要先人工确认。它是“预期中性”的控制，**不保证模型完全不受措辞影响**；如果结果有变化，就按门槛报告校准失败。

### 5.2 共同基线 H*

`H* = 原 Harness 冻结快照 + C_required + C_redundant`。所有组都从 H* 派生，每组只删除指定的一条规则。H* 不是原样的生产 Harness，报告里必须写明这一点，避免把探针结论直接套用到生产删除上。

## 6. spike-000：用量测量

正式实验的预算和时间限制如果没有实测依据，定错一次就会浪费一整轮 25 次运行。spike-000 用最少的调用先测量一次。

| 项目 | 规定 |
|---|---|
| 实验 ID | `spike-000`，独立于 spike-001 |
| 配置 | 只跑 A 配置（H*），使用与 spike-001 相同的任务 |
| 调用次数 | 最多 2 次 |
| 费用上限 | 每次 `--max-budget-usd 1.00`，合计估算不超过 2 USD |
| 单次时间上限 | 600 秒，目的是测出真实时长，不被截断 |
| 需要审批 | 是。属于付费调用，开始前要说明认证方式和计费方式 |

spike-000 同时完成以下探测：

1. 隔离配置目录下能用哪种认证方式，是否只能用 API key 按量计费。
2. 冻结的 `CLAUDE.md` 是否真的被加载，个人记忆、插件、Hooks 和 MCP 是否都被排除。
3. 本机 CLI 版本的 JSON 结果里是否有 `modelUsage` 和 `total_cost_usd` 字段，口径是否和 `claude_result_modelUsage_v1` 一致。
4. 回执验收器能否正确处理 Agent 的真实输出。

**它的结果只用来确定 spike-001 的参数，不参与任何判定。** 两次运行不能并入 A1 或 A2，不计入放弃 L2 主张的次数和费用。产物写到 `experiments/spike-000/`：`probe.json`、`runs.jsonl`、`sizing.md`。

任何一次运行被费用或时间上限截断，都记为 `sizing_incomplete`，不能据此推导预算。重测需要用户批准新的上限，并使用新的 ID（如 `spike-000b`）。

两次运行只能看出量级，看不出波动。所以 spike-000 不用来推算噪声门槛，只用来设定资源上限（见「预算」一节）。

## 7. 正式实验 spike-001：25 次运行

| 组 | 配置 | 次数 | 用途 |
|---|---|---:|---|
| A1 | H* | 5 | 同配置对照一 |
| A2 | H*，与 A1 内容 Hash 相同 | 5 | 同配置对照二 |
| B_real | H* 减去 R_real | 5 | 真实规则的探索性信号 |
| B_required | H* 减去 C_required | 5 | 必要信息控制 |
| B_redundant | H* 减去新增的冗余副本 | 5 | 中性控制 |
| **合计** | | **25** | 包括全部 Target 调用 |

- 分 5 个区组，每个区组里每种配置各跑一次。区组内的顺序事先随机生成并写进 proposal，以保存的 25 项顺序为准。顺序种子只是调度种子，**不是模型的随机种子**。
- 并发固定为 1。每次都是新进程、新工作区、新会话。
- 交错区组而不是一组跑完再跑下一组，是为了降低时间、缓存和服务波动带来的混淆。缓存 Token 必须记录，但不能声称缓存的影响已被完全消除。
- 25 是**最多启动次数**，不是保证完成的次数。启动失败、超时和崩溃都占用原来的位置，不免费补跑，也没有额外的预热调用。
- 任务没通过但进程正常结束、用量记录完整的，算有效的失败结果，不从分母里剔除。缺日志、基础设施错误和被预算截断的，算无效或不完整的运行。快照和验收器的自检不调用模型，不计入 Target 次数，但要记录耗时。

## 8. 指标

| Metric ID | 冻结的计算方式 | 缺失时 |
|---|---|---|
| `test_pass_v1` | 外置真实任务验收器：任务目标和预注册的回归检查都通过才为 1 | 验收器故障记为 unknown，不算模型失败 |
| `calibration_contract_pass_v1` | `test_pass_v1 == 1` 且回执完全匹配 | 没有回执记为 0；验收器失效记为 unknown |
| `total_tokens_v1` | 本次唯一终态结果里 `modelUsage` 各项的 inputTokens + outputTokens + cacheReadInputTokens + cacheCreationInputTokens 之和 | 字段缺失或异常为 0 时记为 unknown，结果为 pivot |
| `wall_time_v1` | 从进程启动到退出的单调时钟秒数；环境准备和验收耗时另外记录 | unknown，结果为 pivot |
| `estimated_cost_usd_v1` | 唯一终态结果里的 `total_cost_usd`，只作为客户端估算 | unknown，结果为 pivot；不猜测真实账单 |

- `total_tokens_v1` 的计算器版本是 `claude_result_modelUsage_v1`，不是跨厂商通用的字段。各项 Token 分量分别保留，缓存 Token 不等同于计费用量。只用结果级字段，不再叠加逐条 assistant 消息。出错的结果也保留。会话崩溃时这些字段可能为 0，不能当作真实用量。[S3]
- **Token 只记录和比较，不作为停止运行的条件。** Claude Code 每一轮都会重新读取缓存的上下文，`cacheReadInputTokens` 会随轮数快速累积，用它做截断很容易误伤正常运行。资源停止条件只用启动次数、时间和估算费用。
- 首次调用前固定计量口径。如果本机版本返回的字段不一样，保留原始输出，pivot 去修正适配器，不能在实验中途换口径继续比较。
- 进程成功退出不等于任务通过。宿主说“已经验证过”不算任何指标。模型分类、满意度和纠正轮数都留到后续阶段，不能代替可执行的验收。

## 9. 预算

资源上限分成两类：固定默认值，以及由 spike-000 推导、冻结前写定的值。

| 项目 | 取值 | 执行方式 |
|---|---|---|
| Target 启动次数 | 25 | 不额外重跑、预热或补样本 |
| 单次进程时间 `T_run` | 默认 180 秒；如果 spike-000 的最长时长超过 120 秒，改为该最长时长的 1.5 倍 | Runner 超时终止，最多留 3 秒清理 |
| 单次 Agent 回合 | 默认 20；如果 spike-000 的回合数接近 20，冻结前由用户确定 | CLI 回合上限，触发上限仍计入本次启动 |
| 单次外置验收 | 30 秒 | 超时记为验收无效，不冒充任务失败 |
| 整个实验墙钟 | `25 × (T_run + 33) + 1800` 秒；默认是 7,125 秒 | 从第一次启动到结束，包括重建和验收 |
| 单次估算费用 `C_run` | spike-000 最高单次估算费用的 2 倍，由用户批准 | 作为 `--max-budget-usd` 传入 |
| 总估算费用 | `25 × C_run` | 每次启动前检查剩余额度 |

- **准入规则：** 剩余的时间和估算费用足够容纳下一次的上限时，才启动下一次。不为了凑满 25 次而临时降低单次上限。成功和失败运行的用量都计入总量。
- **估算费用不是严格封顶。** `--max-budget-usd` 用的是客户端估算，实际花费可能超过上限。[S1][S3] 本协议的硬控制只有启动次数、进程时间、停止准入和权限。用户如果要求真实账单绝不超出，必须有服务商一侧可验证的硬限制，否则不启动。
- 报告里同时写“估算消耗”和“实际账单未知”。不把订阅额度折算成真实的边际花费，也不把缺失字段当作 0。
- 单次估算费用超过 `C_run`、总预算用完或用量记录不完整时，结果为 `pivot`，评估记为 `inconclusive`。不能用模型的主观判断补齐。

## 10. 门槛

记号：`S[g]` 是组 g 的真实任务通过次数；`C[g]` 是“真实任务通过并且回执正确”的次数。两者的分母都固定为 5，是不同的指标，不能混用。

`T[g]` 是组 g 的 `total_tokens_v1` 中位数，`T[A]` 是 A1、A2 共 10 次运行的合并中位数：

```text
N_gap  = abs(T[A1] - T[A2]) / T[A]
N_mad  = median(abs(token_i - T[A]), i in A1 ∪ A2) / T[A]
N_cost = max(N_gap, 2 * N_mad)
```

样本数为偶数时，中位数取中间两个值的平均。MAD 不乘额外的缩放系数。用量缺失或 `T[A] <= 0` 时不能把噪声记为 0，结果为 pivot。

| Gate | 准入条件 |
|---|---|
| 完整性 | 25 次运行都有有效结果，用量按冻结的口径完整记录；没有漂移、泄漏、验收器被改写或生产配置变更 |
| 基线能力 | `S[A1] >= 4` 且 `S[A2] >= 4`；`C[A1] >= 4` 且 `C[A2] >= 4` |
| A/A 质量波动（主门槛） | `abs(S[A1]-S[A2]) <= 1` 且 `abs(C[A1]-C[A2]) <= 1` |
| A/A Token 波动（次门槛） | `N_gap <= τ_gap` 且 `N_mad <= τ_mad` |
| 必要信息可识别 | `min(C[A1],C[A2]) - C[B_required] >= 3` |
| 冗余控制不误报 | `S[B_redundant] >= 4` 且 `C[B_redundant] >= 4`；S 和 C 与 A1、A2 的计数差都不超过 1 |
| 资源 | 满足「预算」一节的全部条件，没有因预算停止 |

- **Token 噪声门槛 `τ_gap`、`τ_mad` 冻结前必须填写。** 建议的默认值是 0.25 和 0.30，但这两个数没有实测依据。spike-000 只有两次运行，无法估计噪声，所以由用户在冻结前确定数值并写下理由。真正的主门槛是通过次数的波动。
- 计数差 3/5 指 **60 个百分点**，不是相对下降 60%。
- 这些门槛检查的是工程上能不能做，不是显著性检验。只有 1 个独立任务组，重复 25 次不能说成 25 个独立任务。

## 11. 判定

### 11.1 探针结论：按固定顺序判定

1. **`invalid_run`**：正式运行中出现生产配置写入、验收器或记录被改写、跨组信息泄漏、冻结的配置或模型发生漂移，或者 Runner 没有执行约定的启动次数或时间限制。立即终止，实验标为无效，不能用来证明规则效果。先修复完整性问题，再用新的实验 ID 重来。`invalid_run` 不计入放弃 L2 主张的次数。
2. **`pivot`**：没有完整性事故，但前置检查或 spike-000 探测没通过，有效运行或用量记录少于 25 次，因预算停止，或者「门槛」一节有任何一条不满足。保存没通过的门槛和原始数据。下一次实验只能换任务、机制或预算，并新建 ID，不修改本次结果。每次 pivot 都计入放弃 L2 主张的次数（见规范的「放弃 L2 主张的出口」）。
3. **`go`**：前置检查、25 次运行、全部门槛和资源条件都通过。只允许进入 **M0 最小 Evaluator**，不代表可以删除 R_real，也不批准建设自动批量 Reasoner。

### 11.2 真实规则信号：单独输出

`probe_decision` 和 `real_rule_signal` 分开输出。B_real 不影响“能否识别人为控制”的判断，只用来看有没有值得后续验证的真实规则信号：

- 只有探针结论为 go 时才解读 B_real。如果 `min(S[A1],S[A2]) - S[B_real] >= 2`，标为 `regression_signal`，原规则保持不变。
- 只有同时满足以下条件，才检查节约信号：
  - `S[B_real] >= max(S[A1],S[A2])`；
  - `C[B_real] >= max(C[A1],C[A2])`；
  - 在每个区组里，B_real 都不低于两次 A 都通过时的质量和回执结果。
- 标为 `follow_up_candidate` 需要同时满足：
  - `saving = 1 - T[B_real]/T[A]`，且 `saving >= 0.15`、`saving > N_cost`；
  - 5 个区组中至少有 4 个满足 `tokens(B_real) < median(tokens(A1),tokens(A2))`。
- 其余情况都是 `inconclusive`。三种结果都**不允许删除生产规则**。后续需要在去掉人工控制的生产等价基线和新的独立任务上另行验证。

### 11.3 冻结与修改

- 修改阈值、验收器、控制规则文本、模型、运行顺序或预算，都要用新的实验 ID 并重新批准。
- 看过结果之后才修改的方案，标为探索性修订，所有失败记录都保留。不能只展示最后通过的那一次，也不能把复用旧结果冒充独立确认。
- 冻结后的 proposal 逐字节计算 SHA-256，存入 `proposal.sha256`。`approval.json` 引用这个 Hash。待批准的模板不能伪装成已冻结的提案。

## 12. 实验目录与报告

```text
${PHE_REPO}/experiments/
  spike-000/
    probe.json                     # 认证、加载链、字段口径的探测结果
    runs.jsonl                     # 最多 2 次运行的原始记录
    sizing.md                      # 推导出的 T_run、回合数、C_run 及依据
  spike-001/
    baseline.json                  # 源仓库、起点、环境和加载链
    rules.json                     # 1 条真实规则 + 2 条人工控制
    proposal.json                  # 填入真实参数后冻结；包括全部门槛和 25 项顺序
    proposal.sha256
    approval.json                  # 用户批准记录、时间、proposal Hash
    runs.jsonl                     # 每次启动占一行，失败也保留
    result.json                    # probe_decision + real_rule_signal
    report.md                      # 原始值、逐条门槛对账、预算、局限
    artifacts/                     # CLI stdout/stderr、Patch、验收输出
```

- M0 继续用 `${PHE_REPO}/experiments/<experiment-id>/`。不在被测仓库里新建 `.phe/` 或 `experiments/`。
- 模板 [`proposal.template.json`](../examples/m-1/proposal.template.json) 是 **draft**。真实路径、模型 ID、版本、Hash，以及由 spike-000 推导的预算和 Token 噪声门槛，都是 null。执行者必须全部填好，确认控制规则和每组的 Patch，获得批准后才写成正式的 `proposal.json` 并冻结。除了明确允许的 `backend_revision="unknown"`，冻结时不允许有必填项未知。
- 冻结后不再写 proposal 的 status 或更新时间，进度只追加到 runs 和 result。每次启动前和汇总前都校验 `proposal.sha256`。Hash 不匹配就停止，不自动重算 Hash 来接受改动。
- 报告必须包括：目标 Agent、模型和任务；生产配置未被修改的证明；5 组的计数和 Token 中位数；N_gap 和 N_mad；每条门槛是否通过；实际用量和缺失的用量；go / pivot / invalid_run 的原因；真实规则的独立信号。不能只给一个总分。

## 13. 故障与边界用例

这些是预期行为测试，不是已经完成的实验。

| 输入或事件 | 必须的输出或行为 |
|---|---|
| 冻结时模板还有路径、模型、Hash、预算或 τ 为 null | 拒绝启动，列出未填项，不猜测 |
| 隔离配置目录下只能用 API key 认证 | 预算审批时明确说明按量计费；用户不同意就不启动 |
| spike-000 的单次时长为 150 秒 | `T_run` 改为 225 秒，总墙钟按公式重新计算 |
| A1、A2 的任务通过数为 5 和 3 | pivot：既不满足基线能力，也超过 1 次的波动门槛 |
| A1、A2 为 5 和 4，B_required 的契约通过数为 2 | pivot：与较弱基线只差 2，小于 3 |
| A1、A2 的契约通过数都是 5，B_required 为 2 | 必要信息门槛通过；其他门槛仍要检查 |
| A/A Token 中位数差的比率超过 τ_gap | pivot：不在事后放宽 |
| 冗余组与某个基线的计数差为 2 | pivot：中性控制不稳定，不宣称“已知无用” |
| 单次 Token 很高，但估算费用在 `C_run` 以内 | 正常记录，不因 Token 停止 |
| 24 次有效运行，另外 1 次崩溃 | pivot，评估为 inconclusive；不追加第 26 次 |
| 单次估算费用超过 `C_run` | pivot；停止后续启动，按完整费用记录，不截断成上限值 |
| 所有门槛通过，但 B_real 没有节约 | 探针 go；real_rule_signal 为 inconclusive；不发布 |
| B_real 恰好节约 15%，但 N_cost 为 0.20 | 没有超过噪声，真实规则信号为 inconclusive |
| 运行中途模型 ID、Harness 或验收器 Hash 变化 | invalid_run：实验失去归因条件 |
| worktree 建在源仓库里并改动了它的元数据 | invalid_run：违反源仓库只读约束；停止并记录，不静默清理来掩盖 |
| 没有用量数据，或崩溃后返回异常的 0 | unknown，结果为 pivot；不把成本当作 0 |

## 14. 交给编码 Agent 的第一个任务

> 读取 `${PHE_REPO}/docs/M-1_PROTOCOL.md`、`docs/PHE_SPEC.md` 和 `examples/m-1/proposal.template.json`，只做 M-1。先确认 PHE_REPO（Harness Grove 仓库）和 TARGET_REPO（被测任务所在的仓库）的绝对路径，不要把当前目录自动当作其中任何一个。先只读核对 Claude Code CLI 的能力、完整模型 ID，以及 1 个历史任务的请求、起点和外置验收器；按协议「前置检查」一节做不调用模型的重建和验收自检。人工确认一条真实的非安全规则，按「规则与对照」一节构造两条控制规则，基于共同基线 H* 生成 5 组 Patch。然后提出 spike-000 的计划，说明认证方式、计费方式和费用上限，**获得用户批准后**才运行，最多 2 次。用 spike-000 的结果填写预算，请用户确定 Token 噪声门槛，填齐全部 Hash 和 25 项运行顺序，展示权限、隐私、总预算以及“估算费用不是硬封顶”的限制。**没有用户批准和 proposal Hash，不得启动正式运行。** 获批后最多启动 25 次，任何失败或崩溃都占用位置，不预热、不补跑、不修改阈值。持久产物只写到 `${PHE_REPO}/experiments/`，执行只在一次性基线仓库的临时 worktree 里进行；源 TARGET_REPO 和生产 Harness 都不改。按「判定」一节的顺序输出 probe_decision，再单独输出 real_rule_signal；不要因为 go 就删除真实规则。不要先开发 SQLite、完整 Schema、跨平台 Runner、Reasoner 或 Idea Inbox。
