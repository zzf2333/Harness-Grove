### 可复现

同一 fixture 连跑两次，两次的 sha256 分别相同：

```text

```

报告刻意保留真实路径（便于用户定位），所以不同 `$WORK` 路径下字节会不同；可复现指的是**同一 fixture 同一路径**的两次运行。报告与结构化结果里都没有运行时间戳。

## 第 1 轮独立审查的 P1 修复（2026-10-31）

三项都在同一入口上，先用正常 CLI 场景复现失败，再改 `tools/workspace.py`。本节追加在上面的验收之后，不覆盖上一节的结果。

### 复现（修前，红）

`$SRC` 是仓库 `tools/` 的副本，`$WORK` 是一次性临时目录，命令从 `$WORK/elsewhere` 跑。

| # | 场景 | 修前证据 |
|---|---|---|
| 1 | `python3 -I "$SRC/tools/workspace.py" init --phe-home …` 前后比对 `$SRC` 树 | 新增 `tools/__pycache__/`，内含 `inventory`、`registry`、`release_deploy`、`release_verify` 四个 `.pyc` |
| 2 | `$WORK/host/.claude/agents/reviewer.md` 与 `$WORK/host/.pi/agent/agents/planner.md` | 目录节点和定义都记成 `kind=instructions`、`能力 沙箱可托管` |
| 3 | adopt → import → release → deploy `--agent claude` 后再 discover | 被部署入口解析到 `releases/r0001/files/asset-0001/AGENTS.md`，报 `未登记`、`asset_id` 为空；同组另一个未部署入口仍报已登记 |

用候选版本跑新增用例是 `FAILED (failures=4, errors=1)`：`KeyError: 'registry_target_matches'`、`'sandbox_managed' != 'observe_only'`、源码树快照多出 `tools/__pycache__`。

### 修复

1. **源码树不留字节码**：`workspace.py` 在导入本地模块前设 `sys.dont_write_bytecode = True`（`-I` 只隔离用户 site 和当前目录，不关字节码写入）。README 的 `python3 -I "$SRC/tools/workspace.py" …` 命令不变。
2. **子代理定义不继承单文件指令能力**：`.claude/agents`、`.pi/agent/agents` 的子代理定义和它们的目录节点在盘点里仍是 `instructions`（`kind` 枚举没有 agent），报告改标 `仅观察`，说明里写明“逻辑类型未支持、不导入也不部署”；instructions 覆盖摘要同样注明这一点。判断只看盘点已有的路径，不加分类框架。
3. **登记身份与当前目标分开**：登记表索引同时收 `resolved_path` 和 `observed` 入口路径，先按入口路径认资产身份，当前目标另外比较。JSON 记录新增 `registry_target`（登记源真实路径）和 `registry_target_matches`；Markdown 在目标变了时写“当前入口 …，不是登记源 …”。

## 第 2 轮独立审查的 P1 修复（2026-10-31）

第 1 轮三项 P1 已修复。本轮只修新增的一项：`workspace.py` 的登记身份索引把“登记来源路径”和“历史 `observed` 入口路径”合成一个字典，按入口优先认身份；入口换绑后，旧资产的 `observed` 入口会遮住后来登记的资产。本节替代上面第 1 轮第 3 项里“先按入口路径认资产身份”的顺序，那一项要解决的“部署后仍认出资产”目标不变；第 1 轮另外两项（源码树字节码、子代理能力标注）不受影响。

### 复现（修前，红）

`$SRC` 是仓库 `tools/` 的副本，`$WORK` 是一次性临时目录，命令从 `$WORK/elsewhere` 跑。

```bash
mkdir -p "$WORK/host/.codex" "$WORK/host/.pi/agent" "$WORK/shared" "$WORK/elsewhere"
printf '共享指令 A\n' > "$WORK/shared/A.md"
printf '共享指令 B\n' > "$WORK/shared/B.md"
ln -s "$WORK/shared/A.md" "$WORK/host/.pi/agent/AGENTS.md"
ln -s "$WORK/shared/A.md" "$WORK/host/.codex/AGENTS.md"
python3 -I "$SRC/tools/workspace.py" init --phe-home "$WORK/phe"
python3 -I "$SRC/tools/inventory.py" --home "$WORK/host" --out "$WORK/inventory-1.json"
python3 -I "$SRC/tools/registry.py" adopt --inventory "$WORK/inventory-1.json" \
    --registry "$WORK/phe/registry/assets.json" --group "$WORK/shared/A.md"
rm "$WORK/host/.codex/AGENTS.md"
ln -s "$WORK/shared/B.md" "$WORK/host/.codex/AGENTS.md"   # 正常用户动作：入口改指另一个真实文件
python3 -I "$SRC/tools/inventory.py" --home "$WORK/host" --out "$WORK/inventory-2.json"
python3 -I "$SRC/tools/registry.py" adopt --inventory "$WORK/inventory-2.json" \
    --registry "$WORK/phe/registry/assets.json" --path "$WORK/host/.codex/AGENTS.md"
python3 -I "$SRC/tools/workspace.py" discover --phe-home "$WORK/phe" --home "$WORK/host"
```

登记表本身是对的（两次 adopt 的 stdout）：

```text
adopted asset-0001 …/shared/A.md (2 个 observed path)
adopted asset-0002 …/shared/B.md (1 个 observed path)
```

修前 `discovery.json` 里两个入口的记录（路径归一化成 `…`）：

```text
codex: asset=asset-0001 target=…/shared/A.md matches=False resolved=…/shared/B.md
pi:    asset=asset-0001 target=…/shared/A.md matches=True  resolved=…/shared/A.md
```

错误在索引：A 的 `observed` 里有 codex 入口，B 登记后同一入口又进 `observed`，`setdefault` 把入口路径留给先登记的 asset-0001。

### 修复

- `registered_index` 返回两个索引：`sources` 按登记的真实来源路径，`entries` 按 `observed` 入口路径。合成一个字典就会让先登记的资产占住入口路径。
- 新增 `registered_asset`：入口当前解析目标命中某个登记来源就直接认那个资产；命中不了（`release deploy` 把入口换成 `releases/r0001/files/<asset_id>/…` 的软链）才按入口路径认身份。同一入口重新登记到另一个来源时，`entries` 取最近登记的资产。
- 报告字段与文案（`registry_target`、`registry_target_matches`、“不是登记源”）和登记表格式都不变。只处理正常登记与发布流程，不加锁、不加 fallback。

### 修复后（绿）

```text
codex: asset=asset-0002 target=…/shared/B.md matches=True resolved=…/shared/B.md
pi:    asset=asset-0001 target=…/shared/A.md matches=True resolved=…/shared/A.md
```

两个正常契约同时成立：发布部署换掉入口目标后仍认出 `asset-0001` 并说明当前目标不是登记源（`tests/test_workspace_release.py::DeployedEntryTests`）；入口换绑并重新登记后认出 `asset-0002`，另一个入口仍是 `asset-0001`（`RelinkedEntryTests`）。新用例在候选版本上是 `FAILED (failures=1)`：`AssertionError: 'asset-0001' != 'asset-0002'`；修复后 `Ran 2 tests in 0.557s / OK`。
